# 《汐湾咖啡馆》技术栈

一套网页代码。现在在浏览器里玩。以后同一套界面用 Electron 上 Steam（PC），用 Capacitor 上手机。这一轮不打包。

播放器是 Vite + TypeScript，普通 DOM 和 CSS。不用游戏引擎，不用 React。分支、隐藏好感、标记、60 天日程都在数据里，播放器不按天数写死。

## 目录

```
05-dev/
  index.html
  src/main.ts              挂上界面
  src/style.css            占位样式
  src/ui/app.ts            标题、对白、选择、地图、存读档
  src/engine/              解析、条件、效果、播放、存档接口
  src/data/                人物、初始标记、日程、背景对照
  src/generated/           构建写出的 story.json（不进 git）
  scripts/build-script.ts  读 03-script，写出 JSON
  test/                    解析、分支、存储、随机周目
```

剧本仍在 `03-script/`。图在 `../assets/`。`_generation/`、`_reviews/` 不是运行时资源，开发服务器和打包都会跳过。

## 剧本怎么变成数据

`npm run build:script` 读 `03-script/day-*.md`，解析失败就停。未知的 `<<<`、看不懂的条件、对不上的去向、缺背景、缺说话人，都抛 `ScriptError`，带文件名和行号。

玩家看得见的行：

| 剧本 | JSON |
| --- | --- |
| 单独一行叙述 | `{ "type": "narration", "text" }` |
| `人名：台词`（人名一到四个汉字，全角冒号） | `{ "type": "dialogue", "speaker", "text", "expr" }`。`expr` 是冒号后的表情，没有就是 `null` |
| 以「开头 | `{ "type": "letter", "text" }` |

`两个字：拿铁` 这种长前缀仍是叙述。`条件`、`选项`、`类型`、`失败`、`效果`、`标记`、`去向`、`占额`、`章节` 不能被当成说话人。

对白的表情写在全角冒号紧后面：`陆屿：[shy]……`。半角 `[...]` 一律当表情，括号里必须是这个人已有的立绘 id（`<拼音>_<id>.png`，可以是 `coat_normal` 这种带服装的）。对不上就构建失败，错误里有文件名和行号，标记不会留在台词里。台词真的要以方括号开头时，用全角 `［］`，原样显示。没标的对白沿用这一场里这个人上一句；这一场还没有，就是 `normal`。换场回到 `normal`。女主、男主替换和分支只算实际演到的那一段，块后面的句子也沿用这一段。`{主角}` 先留在 JSON 里，播放时换成玩家输入的名字，叙述、对白、信和选项标签都换。名字还没输入时不换。效果行、场景名不换。

玩家看不见的行：

| 剧本 | JSON |
| --- | --- |
| `# 第 N 天` | `day`。文件名 `day-NN.md` 必须对上 |
| `# 序章` / `# 第一章` | `chapter` |
| `## 场景：名字` | `scenes[].id`。`##` 先于 `#` 判断 |
| `条件：` | `scene.condition`。一场一个，写在正文前 |
| `效果：` / `标记：` | `{ "type": "effects", "effects" }`，不占画面 |
| `去向：第12天泡面` | `scene.jumps`。有去向就不能再写正文。目标场仍看自己的条件 |
| `> 快进` | `scene.fast` |
| 其他 `>` | 记在 `day.notes`，不当逻辑。例外是第 14 天烟花三行，见下 |
| `<<<替换 名字` | `{ "type": "replace", "byGender": { "男": [], "女": [] } }`。分段只认 `女主` / `男主`。`恋爱` / `友情` 直接失败 |
| `<<<选择 名字` | `choice`。`类型` 只认 `日常` 或 `关键`。`选项：标签 \| 效果：…` |
| `<<<输入 名字` | `input`。`> 记：` 收进 `note` |
| `<<<小游戏 名字` | `minigame`。可再套一层选择。`失败：` 玩家看得见。`>>>` 先于 `>` 判断 |
| `<<<分支 名字` | `branch`。先写条件，再写正文。命中第一条 |
| 不认识的 `<<<` | 失败 |

效果按 `。` 再按 `；` 切开。`女主 陆屿 恋+8`、`许之言女主恋+8，男主友+3` 都认。`恋` 是恋爱，`友` 是友情，夹在 0 到 100。性别对不上的好感跳过。`口碑+N` 记口碑。`好感+0`、`名字+0` 是空操作。句子里没有 `=` 也没有 `+` 的，当成作者备注，丢掉。`标记：看过修网` 这种裸标记写成 `vars[key] = "是"`。`最近自由=某人` 同时记下最近自由，并给这个人的自由次数加一。`登场=某人` 同时写 `登场:某人`，后面的登场不会擦掉前面的。`返回本选择` 停在原选项，并显示失败句。

条件用 `且` 连接。`女主` / `男主` 看性别。`key=value` 必须严格相等，所以 `看过泡面` 在 `initial.json` 里先写成 `否`。单独的 `未看过` / `已看过` 在构建时绑到这一对场景的 `看过*` 标记上：场景名去掉末尾的 `已看`。灯塔已看对的是 `看过读报`，不是 `看过灯塔`。对不上标记时构建失败，错误里有文件名和行号，并请作者改成明确条件，例如 `看过修网=否`。编出来的 JSON 里没有这种半成品条件。播放器若再遇到，当成不成立，不再抛错。`沈若消息未看过` 这种带名字的写法直接查 `看过沈若消息`，不靠成对场景。

第 14 天烟花不写在播放器的天数开关里。这三行必须原文对上，否则构建失败：

- `> 在场：女主为陆屿（第 2 天）、许之言（第 9 天）；男主为夏栀（第 3 天）、唐棠（第 5 天）、叶帆（第 11 天）。`
- `> 低于 20 的不进这场。都低于 20，则秀姨和拿铁。`
- `> 同分：先最近自由；仍同分，比自由次数；仍同分，登场更晚的一位。同第 32 天。`

场景条件 `女主且陆屿恋≥20且陆屿恋为在场最高；…` 收成 `{ "op": "winner", "who", "threshold", "present" }`。唯一最高的人胜出；并列时先看最近自由是不是这一位，再比自由次数，再比谁登场更晚。`当前性别在场可攻略角色的恋爱都低于20` 收成 `belowAll`。沈若不在名单里。

小游戏的「普通」是效果里写了 `表现=普通` 的那一项。手冲、拉花是跳过项。猜谜是第一个成功项（旧咖啡壶）。界面上的「按普通表现继续」就走这项。其余选项仍可点，包括猜谜的 `返回本选择`。

示意：

{
  "days": [{
    "day": 12,
    "chapter": "第一章",
    "fireworks": null,
    "scenes": [{
      "id": "猜谜",

      "fast": false,
      "jumps": [],
      "blocks": [{
        "type": "minigame",

          "type": "choice",

## 播放

`Player` 只看 `story.json`。每天先出一天的卡片，再进入场景。条件不中的场景跳过。效果块不占画面。去向会把另一天的场景插进来播，日历仍停在外面那天：第 10 天去卫生所，播的是第 12 天的泡面。

傍晚地图不是天数判断。选择 id 落在 `schedule.json` 的 `mapChoiceIds`（现在是 `傍晚`）就铺成地图。第 1 到 5 天、第 9、13、14 天剧本里没有这个选择，测试锁着 `eveningMapClosed`。性别选择、名字输入也按 id（`性别`、`名字`）认，不按第几天认。名字去掉空白后要有 1 到 8 个字，写入 `playerName` 和 `vars.主角名`。正文里的 `{主角}` 播放时换成这个名字，男女主共用。这一章正文里还没有这个占位符。

立绘和背景不在剧本里。`presentation.json` 只做背景对照，键是 `天数:场景id`，文件是 `assets/backgrounds/<id>/<id>.png`。没有服装表。立绘文件由表情决定：`assets/portraits/<拼音>/<拼音>_<表情>.png`。没写表情时这一场这个人从 `normal` 起，之后沿用上一句，换场再回到 `normal`。替换块和分支里没演到的句子不算。来电在读到含「你打开门」的句子后换成门外的夜景，这场剩下的句子保持这张。说话人「电话」没有立绘，不能写表情。立绘跟这场已经说过话的最后一个人，表情按已显示的行重算，读档也一样。

手机窄屏（宽高比不超过 3:4）时背景画布宽 125%、水平居中，左右各裁掉大约一成。背景按 1920×1080 出图，立绘 1536×2304 透明 PNG，猫 1024×1024。

`schedule.json` 里 `totalDays` 是 60。播放器能播多少天，取决于有哪些 `day-*.md`。现在是 14 天。

## 存档

`SaveStorage` 是异步的 `read` / `write` / `remove` / `list`。浏览器实现走 localStorage。存档键是 `sc/save/<档位>`。自动档加 3 个手档。格式版本 `v: 1`，含位置、状态、摘要，以及 `scriptVersion`。`v` 不是 1 就拒绝读。Electron 或 Capacitor 以后换文件实现，播放器不动。

`scriptVersion` 是构建时对编译后的 `days` 做的 SHA-256，写在 `story.json` 的 `version` 里，不把版本号自己算进去。每份新档都会记下它。读取时如果和当前剧本不一致，或者旧档没有这个字段，先告诉玩家：这份存档是另一版剧本写下的。玩家可以仍要读取，也可以回到标题。仍要读取之后，如果进度对不上、播放器报错，就回到标题，并说明这份存档读不了。版本不一致不会直接把档删掉。

设置（文字速度、字号）走同一个 `SaveStorage`，键是 `sc/settings`，不进存档档位。这一轮没有声音。换 Electron 或 Capacitor 的存储实现时，设置跟着走。

## 第 1 轮做了什么

做了：标题、性别和名字、对白、立绘、背景、选择、好感和标记、用到傍晚地图的晚上、存读档、回顾、最少的设置、可跳过的小游戏占位（按普通表现结算）、从标题走到第 14 天结束。两条性别都走得通。

没做：真正的手冲、拉花、猜谜；声音；Electron / Capacitor；正式界面。界面是占位，等 Alex。

## 剧本不一致，播放器不改原文

1. 许之言的 `标记：登场=许之言` 只写在「留下许之言」。占额和第 14 天在场名单仍把他算成第 9 天登场。`登场效果另计` 的好感在「钉窗」里总会加上；登场标记只在留下他时写入。播放器不补这个标记。
2. `烟花=此人` 只出现在「烟花很低」。其他烟花场没有效果行，`vars.烟花` 不会记下是谁。很低那场的值就是原文「此人」。
3. 拿铁、老夏这一章不开口，所以不出立绘。电话是说话人，没有图。
4. `> 比较：` 一类自由格式的 `>` 只当备注。烟花规则只认上面那三行固定句。
