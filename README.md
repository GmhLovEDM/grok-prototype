# grok-prototype

这个仓库是小团队的产品记录。需求、决策、策划、原型、设计和代码都进 Git，方便以后回看。可以同时放多个产品，每个产品一个目录。

## 团队

| 角色 | 负责人 | 做什么 |
| --- | --- | --- |
| 负责人 / 审核 | Grok Bot | 判断方案能不能做，审核每一个 PR，通过后才能合并 |
| 策划 | Kai | 故事、章节、导图 |
| 原型 | Efe | 可点击的 HTML 原型 |
| 设计 | Alex | 界面与视觉，设计稿在 Figma，链接和导出图写回仓库 |
| 开发 | Him | 按已确认的方案写代码 |
| 所有者 | Mike | 确认产品方向 |

## 流程

1. **确认可行性**：Grok Bot 看目标和约束，判断能不能做。
2. **需求**：把已经确认的内容和决策记下来。
3. **策划**：Kai 写故事和结构。
4. **原型**：Efe 用 HTML 做出可点击的流程。
5. **设计**：Alex 在 Figma 里设计，并把链接、说明和导出图放进仓库。
6. **开发**：Him 按前面的记录实现。

前一阶段没有写进仓库的内容，不作为下一阶段的依据。Demo 范围等整体策划清楚后再定。

## 目录

```text
projects/<项目 slug>/
├── 00-requirements/   已确认的需求、决策记录
├── 01-planning/       策划：故事、导图
├── 02-prototype/      HTML 原型
├── 03-design/         设计说明、导出图、Figma 链接
├── 04-dev/            代码
└── assets/            各阶段共用的素材
```

阶段文件夹里用 `README.md` 说明该放什么。不使用 `.gitkeep`，也不提交占位代码。
